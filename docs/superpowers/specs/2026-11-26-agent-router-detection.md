# Codex / Claude Code 识别与配置写入修正

## 目标

残留配置不能让未安装的 Codex 或 Claude Code 显示已识别。已安装但配置尚未生成时，仍能识别软件。配置写入使用与终端一致的默认目录，同时保留用户手动选择的路径。

## 方案比较

- 只修改“已识别”文案为“已找到配置”：改动最小，但不能回答软件是否安装，也不能修复终端与 Electron 默认目录不同的问题。
- 增加独立安装状态，保留配置检查和写入能力：推荐。两种状态各自表达准确的信息，支持预先配置。
- 未安装时完全禁止写入：会取消现有的预先配置能力，不推荐。

## 推荐实现

1. 复用 `src/main/utils/shell-env.ts` 和 `src/main/utils/process.ts` 获取登录终端环境、查找命令并执行带超时的 `--version` 检查。Claude Code 检查 `claude`，Codex 检查 `codex`。版本输出需与对应工具匹配，失败不能当作已安装。
2. Codex 在 macOS 上兼容只安装桌面应用的情况，检查应用包和 Bundle ID。安装状态由可用 CLI 或匹配的桌面应用决定。
3. 安装状态独立于已有的配置检测状态；配置格式异常仍显示需要处理，不能显示配置就绪。
4. 默认目录读取登录终端环境中的 `CODEX_HOME` / `CLAUDE_CONFIG_DIR`，没有设置时使用现有用户目录。用户选择配置后不再自动替换该路径。
5. 保留缺失配置的创建、预览、备份、版本冲突检查及事务写入。安装未识别时允许预先配置，但明确说明写入的是配置，不保证软件已经使用它。
6. 显示当前写入路径，避免默认目录或手动选择目录不一致时无法判断写到了哪里。不承诺能判断所有 CLI 启动时的临时环境变量或项目级覆盖。

## 验证

- 只有残留配置、没有可用命令：安装状态为未识别，配置状态单独保留。
- 命令可用、配置缺失：安装状态已识别，可以创建配置。
- macOS 只有 Codex 桌面应用：安装状态已识别。
- 错误版本输出或命令超时：不当作可用 CLI。
- 登录终端设置自定义配置目录：默认读写使用该目录。
- 用户手动选择配置：刷新后保留选择。
- 配置异常、并发修改：不能误报就绪或覆盖冲突。
- 针对修改运行主进程、页面测试和 TypeScript 检查；保留所有已有无关改动。
